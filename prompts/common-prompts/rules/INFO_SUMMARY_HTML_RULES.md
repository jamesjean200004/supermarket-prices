# INFO_SUMMARY_HTML_RULES.md

触发条件：Human 要求做或更新"信息汇总"（把一个主题的信息整理成一页 HTML）；或者 repo 里有 `info-summary/信息汇总-Summary-索引.html`，AI 开始或恢复任何任务（见下面 `开工先读，做的过程中和做完就改`）。入口见 `AGENTS.md` 的 `规则索引：什么任务读哪个文件`。通用的网页规则（字少、图优先、细节默认收起、版式、颜色、易于检索、页面里不放代码、交付前实际看一遍）在 `HTML_PAGE_RULES.md`，这里只写信息汇总额外的要求。写完怎么检查在 `prompts/common-prompts/review/INFO_SUMMARY_HTML_REVIEW.md`。

来源：2026-10-27 v-project 里做的几个信息汇总 HTML（Human 评价"非常清晰"）；2026-10-30 AZZU-3296 版式试验（Human 评价"非常满意"）。

## Always Mandatory

### 目的

- **一个任务的信息都在这里**：每个任务的汇总信息都放进信息汇总；读者 3 分钟内拿到 high level 信息，想看细节再点开。
- **Human 会读的都在这里**：2026-11-13 起任务索引、定下的规则、账号和服务、看不懂记录、给 Human 看的文档也都写成信息汇总，不写 `.md`（清单见 `PROJECT_STATE_RULES.md` 的 `Human 会读的都写成信息汇总`）。
- **取代 HLF**：2026-11-02 起不再写 HLF；旧 HLF 可以读来了解以前的 context，但只读不写。Zero-context AI 接手要用的东西都写在信息汇总里：当前步骤、下一步、决定、blocker、evidence、关键 repo / code 路径；细节放进点开才看到的详情。老任务怎么迁移见 `PROJECT_STATE_RULES.md` 的 `HLF 停用`。

### 开工先读，做的过程中和做完就改

- **开工先读**：repo 里有 `info-summary/信息汇总-Summary-索引.html` 时，AI 开始或恢复任何任务前，先读总索引，再读和这个任务相关的信息汇总（这个任务自己的页面、它的上下层页面）；没有相关页面就跳过。
- **做的过程中就改**：出现新决定、新 blocker、验证结果或下一步变化，当轮更新相关页面；同一个事实出现在别的页面时一起改。
- **做完就改**：任务完成、暂停或取消时，更新相关页面的状态和时间线，以及总索引那一行的状态和说明。
- **直接 push，不走 PR**：Personal Project 里信息汇总 HTML 单独 commit、直接 push `main`，不放进工作的 PR（见 `AGENTS.md` 的 `信息汇总直接 push`）。

### 文件放在哪、叫什么

- **放在哪**：Repository 根目录的 `info-summary/`；项目可以在 `PROJECT_LOCAL_OVERRIDES.md` 改位置。
- **文件名必须同时有日期、"信息汇总"和 "Summary"，有 ticket 编号的必须带编号**：格式 `YYYY-MM-DD-<ticket 编号>-<主题>-信息汇总-Summary.html`，没有编号就是 `YYYY-MM-DD-<主题>-信息汇总-Summary.html`，这样按"信息汇总"或"Summary"都能搜到。日期是第一次创建的日期，以后更新不改文件名。
- **从模板开始**：新建汇总时复制 `prompts/common-prompts/templates/INFO_SUMMARY_TEMPLATE.html`，只换内容。

### 共用样式和脚本

- **为什么**：信息汇总的整套 CSS/JS 约 23k～25k 字符，写在每页里时约占页面一半；AI 每读、每写一页都要为它多花 token。放进共用文件后，每页只剩内容。
- **共用文件在哪**：`info-summary/assets/summary.css`（样式、字体和总索引的一行一页列表 `.idx`）和 `info-summary/assets/summary.js`（本页目录、点击后从底部弹出的详情、搜索、手机菜单、淡入、步骤流程图的收起展开、命令的复制按钮）。Canonical source 是 Common repo `common-user-preferences-hub`（GitHub `jamesjean200004/common-user-preferences-hub`）`main` 上的同路径文件。
- **只引用共用文件**：信息汇总页面都放在 `info-summary/` 里，所以 `<head>` 用相对路径引用 `assets/summary.css` 和 `assets/summary.js`（字体由 `summary.css` 加载）；页面里不写 `<style>` 块，也不写 JS 代码。
- **唯一例外是详情数据**：点主图方块、时间线时显示的详情，写在页面底部唯一一个 `<script type="application/json" id="details">` 里，只放数据：key 等于元素的 `data-k`，值是 `[标题, [[字段, 值], ...]]`，写法照模板；某个值是要复制的命令时写成 `[字段, 命令, "cmd"]`，显示时旁边带“复制”按钮。
- **repo 里还没有共用文件时**：先把 Common repo `main` 上的 `info-summary/assets/` 两个文件原样复制到本 repo 同一路径，再写页面。
- **共用文件只在 Common 改**：各 repo 不改本地副本；要改样式或行为，就在 Common repo 改（走 `COMMON_RULES_SYNC.md` 的 PR gate），merge 后再同步到各 repo。
- **新样式和新交互也放共用文件**：页面需要新的样式或点击效果（例如可以收起的步骤流程图、复制按钮）时，加进共用的 `summary.css` / `summary.js`，不在单个页面里写（2026-11-09 Human）。
- **不合格就打回重做**：`INFO_SUMMARY_HTML_REVIEW.md` 第 4 项“共用样式和脚本”不通过的页面不能交付，改好后重新检查第 4 项和改动碰到的地方（按 `AGENTS.md` 的 `Review 有终点`）。
- **旧页面顺手换**：更新一个还在页面里自带 `<style>` / JS 的汇总时，一起换成引用共用文件，并在浏览器里对照确认显示和点击效果没变。

### 分层：总索引 → Ticket → Subtask，最多三层

- **第 1 层 · 总索引**：`info-summary/信息汇总-Summary-索引.html`，每个汇总一行（日期、标题、一句话说明、状态、链接），按层级缩进，可以搜索；新建、移动或删除汇总时同时更新索引。2026-11-13 起它也是任务索引：还没做完、只有 PR 的小任务也各占一行（链接 PR），PR 合并后删掉那一行；取代 root `ZERO_CONTEXT_AI_HANDOFF_TASK_INDEX.md`（写法见 `PROJECT_STATE_RULES.md` 的 `总索引 = 任务 + 信息汇总`）。
- **总索引不按状态分组**：总索引只按这三层排，同一个 Ticket 或 Topic 的页面放在一起，不按状态拆开；状态只用颜色小圆点标在每一行上。
- **第 2 层 · Ticket**：每个 Ticket 一个主汇总，讲这个 Ticket 的全貌；没有 Ticket 的任务单独一个汇总，也算第 2 层；账号和服务、规则信息汇总、看不懂记录、给 Human 看的文档这类独立主题也算第 2 层。
- **第 3 层 · Subtask 和专题**：Ticket 下的每个 Subtask 一个汇总；Ticket 的会议、PR、测试等专题也可以单独成文件，挂在这个 Ticket 下面，算第 3 层。
- **不超过三层**：第 3 层下面不再建文件；Subtask 自己的会议、PR、测试信息并进这个 Subtask 的汇总。
- **上下互相链接**：下层页面顶部链接回上一层；上层页面列出并链接所有下层。

### 不重复主题

- **一个主题一个文件**：一个主题只能有一个信息汇总文件。有新信息就更新原文件，不新建第二份，并更新页面上的"最后更新"日期。
- **新建前先查**：新建前先看总索引；已经有同一主题（同一个 Ticket、Subtask、会议、PR 或测试）的文件，就更新它，不再新建。

### 不重复信息、不冲突

- **一个事实只在一个文件里写详细**：一个事实（状态、名字、数字、决定）只在负责它的汇总里写详细；其他汇总只写一句结论，再链接过去，不再写一份。
- **一处改了，其他地方一起改**：新信息改变了某个事实时，所有提到它的汇总一起更新。发现两个汇总说法不一样，按最新的 evidence 改掉旧的；查不清哪个对，两边都标"待确认"并问 Human。

### 不过时

- **页面是现在的真实情况**：状态、下一步、日期、数字要和最新 evidence 一致（`git log`、Ticket、部署结果、其他汇总）；发现过时的就当轮改掉。
- **做完的下一步挪走**：已经做完的“下一步”移到时间线，不留在状态块里。
- **写具体日期**：不写“今天”“下周”这类相对时间，写具体日期。
- **索引跟着页面**：总索引那一行的状态、说明和链接，要和页面一致。
- **最后更新**：每次更新都改页面上的“最后更新”日期。
- **查哪些页面**：只查总索引、这个页面的上下层页面，以及按关键词搜到的、提到同一事实的其他汇总；不需要每次打开全部汇总。

### 写完要检查

- **每次都查**：新建或更新信息汇总后，按 `prompts/common-prompts/review/INFO_SUMMARY_HTML_REVIEW.md` 逐条检查，结果写进回答的 `## 🗂️ 信息汇总 Review`；第 1～6 项（不重复、不冲突、不过时、共用样式和脚本、一眼看懂、事实有出处）和第 9 项（主图）是必查重点。
- **列给 Human 审核**：新建或更新的汇总文件，写进回答的 `## 📁 等待用户审核的文件+PR`（写法见 `AGENTS.md` 的 `等待用户审核的文件+PR section`）。

### 页面结构（从上往下）

1. 结论：顶部蓝色渐变区，一句话说清楚现在是什么情况，加最多 4 个关键事实（编号、时间、状态、关键 resource）。
2. 主图（**必须有**，固定是第 2 块）：这一页最重要的一张图，形式从 `HTML_PAGE_RULES.md` 的 `常用图形` 13 种里按内容选，可以组合；见下面的"主图"。
3. 状态（**必须有**）：现在到哪了、要先处理的事、谁要做什么（我要做 / 等团队）；检查清单默认收起。
4. 时间线（**必须有**）：什么时候做了什么、发生了什么；已发生、现在、计划用不同样式区分；点时间点看细节。
5. Q&A（**必须有**）：默认只显示问题，点 "+" 看答案；问题用 Human 会搜的说法写；搜索框也过滤这里。
6. 来源：放在页脚，链接到原始文件、ticket、会议，写上日期。

- **固定 5 块**：上面 1～5 每页都有，顺序不变（来源在页脚，不算）；其他信息（重点表、试过不行的方案、上线顺序等）放进合适的块里，默认收起。
- **Human 要加的 section**：Human 随时可以要求加别的 section，这是允许的：单独成一块，不省略、不并进别的块，也不算在固定的 5 块里；放在 Human 说的位置，没说就放在时间线和 Q&A 之间。AI 自己不加固定 5 块以外的块。
- **本页目录**：每一页（包括总索引）都有只管这一页的目录，放在顶部导航栏的第一个，名字叫“目录”；点开列出这一页的每一块和每张图（`图 N：标题`），点一行就跳过去，标题露在导航栏下面。2026-11-05 Human 定的。
- **目录自动生成**：目录由共用 `summary.js` 按页面里的块标题和图标题自动生成，页面不手写、不维护第二份，所以内容改了目录也跟着变；为此每一块都要有 `h2` 标题，每张图的标题写在 `.eyebrow` 里、以 `图 N` 开头。导航栏里不手写目录链接：手写了（链接指向 `#toc` 或文字是“目录”）共用 JS 就不再加下拉目录，页面又会变回两种目录。页面里的目录图（例如面试综合页第一节）可以保留，它会作为一行出现在下拉目录里。2026-11-07 Human 定：所有页面统一用下拉目录。

### 主图

- **为什么叫主图**：第 2 块以前叫“架构图”，读起来像只能画架构；2026-11-04 Human 改名为“主图”：它是这一页最重要的一张图，可以是架构，也可以是进度条、时间线、柱状图、对比卡片等。
- **形式按任务内容选**：先找出这个任务最关键的东西（关系、步骤、数量、对比），再从 `HTML_PAGE_RULES.md` 的 `常用图形` 13 种里选形式（例如分区架构图把 Subscription、环境当大区块，进度条看完成度），可以组合；清单外的图只有确实更合适时才用；说得出为什么选这种；不固定用 draw.io 式方框箭头。
- **内容要全**：这个任务最关键的东西都要在图上；画的是架构类图时，组件、它们在哪（Subscription / Resource Group / 环境）、它们之间的关系、例外情况都要在图上；改版时对照旧图，不能漏东西。
- **方块上只写名字**：方块写编号和名字加一行说明（编号规则见 `AGENTS.md` 的 `每个框都编号`）；点方块，详情从屏幕底部弹出，显示完整信息（ID、role、状态、来源）。
- **详情从底部弹出**：点方块或时间线后，整页变暗，详情面板从屏幕底部弹出，不用往下翻；点暗的地方、点 × 或按 Esc 关掉；详情太长时在面板里滚动。这个行为写在共用 `summary.js` / `summary.css` 里，页面不用改，也不自己写一份。为什么：图比屏幕高时，图下面的详情框在屏幕外，Human 要来回翻（2026-11-13 Human 定）。图下面的 `.dt` 只放一行提示。
- **连线上的字尽量短**：只写关系，例如"写入"、"备份"、"分配 policy"。
- **颜色和图例**：类别用蓝和深蓝，状态用红、黄、绿、紫（见 `HTML_PAGE_RULES.md`）；图下面放图例。
- **文字密度**：每格、每行 1～2 句；Q&A 的答案尽量 1～2 句；整页字数见下面的 `字数上限`。

### 字数上限

- **为什么**：目标是字越少越好，用图代替字。2026-11-02 Human 看过 AZZU-3296 页面后觉得字还是太多（不点开时约 2500 字）。
- **不点开最多 1500 字**：页面不点开任何东西时看得到的字，最多 1500 个；总索引也一样。
- **怎么数**：中文一个字算 1 个，英文一个单词算 1 个；默认折叠的内容、图里的字（`.diagram` 里的 SVG 和方块）、导航栏、页脚都不算。
- **超了怎么办**：先把能画成图的改成图，再把细节放进默认折叠的详情；还超就拆出下一层页面（第 3 层）；第 3 层还超就只能继续折叠，不建第 4 层。
- **旧页面**：更新一个超过 1500 字的旧页面时，一起改到 1500 以内。

### 数字用图表

- **为什么**：数字的变化和比较写在句子里，读者要自己在脑子里比大小；画成图，一眼就能看出谁多谁少、降了多少。
- **数字画成图**：页面里表示多少的数字（数量、读写次数、金额、时长、百分比、用量等）都画成图，不能只写在句子里。从 `HTML_PAGE_RULES.md` 的 `常用图形` 里按内容选：
  - **变化**：改前 → 改后、降了或涨了多少，用柱状图（前后两根柱子）。
  - **比较**：几个阶段、场景、方案之间比大小，用柱状图。
  - **随时间**：按天、按周的变化，用折线图。
  - **对上限或预期**：用量对额度、实际对预期，用进度条，写实际数值和单位。
  - **几个值在同一条刻度上比**：看谁高谁低、离目标多远，用点状图。
  - **几个对象、几项数字一起对照**：用分组柱状图。
  - **几个独立的关键数**：用数字卡片，或顶部结论区的关键事实。
- **不用表格代替图**：表格里的数字还是文字，读者照样要自己比大小，所以数字不放进表格展示。
- **文字只写结论**：图旁边只写一句结论；数值和单位写在图上，更细的数字放进点开的详情。
- **只有编号和日期留在文字里**：日期、PR 编号、ticket 编号、ID 这类不表示多少的数字，照常写在句子里。
- **结论句里的数字也要在图上**：结论句可以引用数字，但这个数字必须同时出现在图上。
- **怎么画**：用 inline SVG 画在 `<div class="diagram">` 里（共用 CSS 已经支持，字号 16px）；颜色只用 `HTML_PAGE_RULES.md` 规定的几种。

## Scenario-Based Mandatory

### 已有的 Markdown 汇总

触发条件：Repository 里已经有同一主题的 Markdown 汇总，或 Human 要求整理旧的汇总文件。

- **新的一律用 HTML**：新的信息汇总不再写成 Markdown。
- **迁移后才删除**：先把旧 Markdown 里仍然有用的内容迁入对应主题的 HTML，确认没丢内容后再删除旧文件（按 `MARKDOWN_DOCUMENT_RULES.md` 的 `重构不丢内容`）。
- **重复的合并**：同一主题有多个汇总文件时，合并成一个 HTML。

### 旧版式的汇总

触发条件：更新一个还是旧版式（不是 Apple 式布局加红黄蓝绿紫的配色）的汇总。

- **顺手换新版式**：更新内容时一起换成模板的版式，并对照旧页面确认内容没有丢。
