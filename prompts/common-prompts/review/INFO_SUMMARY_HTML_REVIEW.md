# INFO_SUMMARY_HTML_REVIEW（信息汇总审核规范）

| 项目 | 内容 |
|---|---|
| 更新时间 | 2026-11-17 |
| 目的 | INFO_SUMMARY_HTML_REVIEW 回答的是 HOW TO VERIFY：信息汇总 HTML 写完以后，怎么逐条确认它符合规则，并且和其他汇总不重复、不冲突、不过时。 |
| 文档语言 | 本文件以中文为主；HTML、SVG、ticket、evidence、section 等 technical terms / proper nouns 保留 English。 |
| 适用范围 | 每次新建或更新信息汇总 HTML 都必须执行；本轮没有新建或更新信息汇总时，回答里的 section 写 `➖ N/A`。 |
| 对应关系 | 本文件镜像 `INFO_SUMMARY_HTML_RULES.md` 和 `HTML_PAGE_RULES.md`；Rules 规定"必须怎么做"，Review 只检查"有没有做到"，不维护第二套规则。 |
| History | 旧版本和变化过程由 Git history 保留；本文件只维护 current review contract。 |

## Mandatory Requirements

### Review Output Contract

| 规则 | 一句话说白了 |
|---|---|
| 独立 Chat Section | 回答里必须有顶层 section：`## 🗂️ 信息汇总 Review`；本轮没有新建或更新信息汇总时，下面只写一行 `➖ N/A`。 |
| 先查别的汇总 | 第 1～3 项（不重复、不冲突、不过时）和第 7 项（分层和索引）必须实际打开总索引、这个页面的上下层页面，以及按关键词搜到的、提到同一事实的其他汇总来查，不能只凭记忆；不需要打开全部汇总。 |
| 回答里只写结果 | 和 `AGENTS.md` 的 `Answer Review`、Coding Standards Review 一样：检查全部照做，回答里只写一行结果，有问题才展开（见下面 `信息汇总 Review Report Shape`）。 |
| Mandatory checks | AI 每次都按顺序逐条检查下方 12 个 Mandatory checks，不能跳过；第 1～6 项和第 9 项（主图）是必查重点，`AGENTS.md` 的 `信息汇总 Review section` 点名要求。 |
| Status | 每项使用 ✅符合 / ❌不符合 / ⚪N/A / 🟡UNVERIFIED。 |
| Evidence | 每一项检查都必须有最小真实 evidence；⚪N/A 要有原因；🟡UNVERIFIED 要说清缺什么 evidence。全部通过时 evidence 不写进回答，但 Human 问起时必须能给出。 |
| Conditional checks | 当前汇总满足条件的 Conditional Review 必须逐条检查；不适用的不机械展开。 |
| No fake PASS | 没有实际在浏览器里看过、没有实际打开别的汇总比对过，不得写 ✅符合。 |
| Fix loop | 任何一项是 ❌不符合，这个页面就打回重做：改好后重新检查那几个 ❌ 和改动碰到的地方，都通过才能交付；不能把已知问题包装成 Done。什么算 ❌、复查范围和最多 3 轮，按 `AGENTS.md` 的 `Review 有终点`。 |

### Mandatory Review Checks

| # | 检查项 | 一句话说白了 | 怎么判断 | Evidence |
|---:|---|---|---|---|
| 1 | 不重复 | 同一个事实、同一个主题，是不是只在一个汇总里写详细？ | 打开总索引，找出同一个 Ticket、Feature、系统或同一批 resource 的其他汇总，逐个比对：重复的内容只留在负责它的汇总里写详细，其他地方改成一句结论加链接；新建前查过总索引，没有同一个 Ticket、Subtask、会议、PR 或测试的旧文件，有的话是更新旧文件而不是新建。 | 查过的文件名 + 发现的重复（没有就写"无"）。 |
| 2 | 不冲突 | 同一个事实在不同汇总里说法一样吗？ | 比对状态、名字、ID、数字、日期、决定；这次改了的事实，所有提到它的汇总都已更新；查不清哪个对的，两边都标"待确认"并问 Human。 | 比对过的事实 + 一起更新的文件。 |
| 3 | 不过时 | 页面上的内容是不是现在的真实情况？ | 状态、下一步、日期、数字和最新 evidence（`git log`、Ticket、部署结果、其他汇总）一致；已经做完的“下一步”已移到时间线；“今天”“下周”这类相对时间写成具体日期；总索引那一行的状态、说明和链接与页面一致；页面“最后更新”日期是今天。 | 对照过的最新 evidence + 改掉的过时内容（没有就写"无"）。 |
| 4 | 共用样式和脚本 | 页面是不是只引用共用 CSS/JS，自己不带一份？ | `<head>` 引用 `assets/summary.css` 和 `assets/summary.js`；页面里没有 `<style>` 块，也没有 JS 代码；唯一的 `<script>` 是 `type="application/json" id="details"` 的详情数据；本 repo 的 `info-summary/assets/summary.css` 和 `summary.js` 与 Common repo `common-user-preferences-hub` `main` 上的同路径文件 exact match；版式和颜色由共用 CSS 保证，页面内容自己还要做到：没有 emoji 和背景图；主图 SVG 里只用红、黄、蓝、绿、紫加白和灰；红点只给真正要先处理的事。 | `<style>` / `<script>` 的搜索结果 + 和 Common 比对的结果 + emoji / SVG 颜色检查 + 用到红点的地方。 |
| 5 | 一眼看懂 | Human 3 分钟内能看懂重点吗？ | 第一屏是结论；每格、每行 1～2 句；Q&A 答案、检查清单、详情、试过不行的方案默认收起；每张图先全貌后细节：第 1 层大组不超过 5 个（组里的方块不算），步骤流程画成两列（HTML 方框，左列 Stage、右列 Steps 分组，Steps 默认收起，点 Stage 展开，有“全部展开”按钮；状态用 ✅ 🟡 ❌ ⬜ 加字，不用图例；一页有几个测试时，Stage 写明测试和对象），层级的下级默认收起；命令旁边有“复制”按钮，关系图上面有一句话说全貌；卡片一行一张，没有左右并列；两张以上卡片的块，上面有一句话说清这些卡片是什么、为什么放、什么关系；技术名词、resource / service 名称、术语是 English，其余是中文（团队页全 English）；所有文字不小于 16px；不点开时看得到的字不超过 1500 个（数法见 `INFO_SUMMARY_HTML_RULES.md` 的 `字数上限`）；关系、结构、架构、流程画成了图，没有写成文字；每张图都标了 `图 N：标题`，文字里提到的图号和图上一字不差。 | 默认展开的内容 + 最长的几格 + 数出来的字数 + 图号列表。 |
| 6 | 事实有出处 | 页面上的事实能找到来源吗？ | Resource、subscription、repo 等写完整名字和 ID；状态、数字、决定能指到 evidence；不知道的写 `UNKNOWN` / `UNVERIFIED`，不猜；页脚有来源和日期。 | 来源列表 + `UNVERIFIED` 的项。 |
| 7 | 分层和索引 | 在“总索引 → 第 2 层 → 第 3 层”里位置对、能找到吗？ | 第 2 层是 Ticket 主汇总（或项目 override 规定的第 2 层）或没有 Ticket 的独立任务；第 3 层是 Subtask 或挂在第 2 层下的会议、PR、测试；没有第 4 层；下层顶部链接回上层，上层列出所有下层；总索引按层级缩进、有这一行，没有按状态分组，状态用颜色小圆点标；放在 `info-summary/`（或项目指定位置）；文件名是 `YYYY-MM-DD-<ticket>-<主题>-信息汇总-Summary.html`。 | 文件路径 + 层级 + 上下层链接 + 总索引那一行。 |
| 8 | 页面结构 | 必须有的块都有、顺序对吗？ | 固定 5 块都有，顺序是结论 → 主图 → 状态 → 时间线 → Q&A（主图固定是第 2 块），来源在页脚；Human 要求加的 section 都单独成块、没被省略或并进别的块，不算在 5 块里；除此以外没有 AI 自己加的顶层块；顶部导航栏第一个是“目录”，列出这一页的每一块和每张图（每块有 `h2`，每张图的 `.eyebrow` 以 `图 N` 开头，目录才列得全）；从 `prompts/common-prompts/templates/INFO_SUMMARY_TEMPLATE.html` 开始。 | 页面 section 列表 + 目录里的行数和页面的块、图数量对得上。 |
| 9 | 主图 | 第 2 块有主图、形式选对了、内容全吗？ | 强制自检，每次都查：第 2 块有一张主图，标了 `图 N：标题`；形式是 `HTML_PAGE_RULES.md` `常用图形` 13 种之一或组合（清单外的要说得出为什么更合适）；说得出为什么选这种形式；这个任务最关键的东西都在图上（架构类图要有组件、所在位置、关系、例外）；改版时对照过旧图没漏；点方块能出详情；有图例。流程 / 步骤图（主图和页面上其他图）每个 Stage 和 Step 最前面都有 ✅ 🟡 ❌ ⬜ 之一并跟着字，没有用 ⏳、彩色圆点或 🟢 🔴 标步骤状态（`AGENTS.md` 的 `步骤状态 emoji`）；做过的 Step 方块上写了用时，等得久的标了 ⏰，点开的详情里有开始、结束时间和等了多久；只有 Stage 和 Step 两层，手机上 Step 也明显缩进在 Stage 下面（`AGENTS.md` 的 `Stage / Steps 和用时`）。 | 用的哪种图形 + 选它的理由 + 和旧图的对照 + 步骤状态 emoji 和用时查了几步。 |
| 10 | 代码、已有文档和链接 | 页面里有没有塞代码、重写已有文档？Human 要去的地方能一点就到吗？ | 脚本链接到 `scripts/` 里的文件，policy 定义、配置也链接到单独文件，页面里只有一两行的短命令（项目 override 允许的“给 AI 的细节”块除外）；已有文档只写步骤并链接；所有相对链接指向的文件都存在；Human 要去看或操作的东西（pipeline、审批、Azure resource、PR）链接直达那一页（`HTML_PAGE_RULES.md` 的 `资源链接直达那一页`）；要 Human 跑 pipeline 的步骤列了 branch 和全部参数，一个一行，选的 `✅ True`、不选的 `❌ False`。 | 页面里的命令 + 链接检查结果 + 直达链接和 pipeline 参数检查结果。 |
| 11 | 电脑和手机实际看过 | 在浏览器里看过、没有显示问题吗？ | 375px 和 1280px 以上各看一次：没有横向滚动、文字重叠、截断、连线穿过方块；手机菜单能打开和收起；目录能点开，点一行跳过去，标题不被导航栏挡住；搜索框能过滤 Q&A；点方块，详情从屏幕底部弹出，点暗的地方、× 或 Esc 能关掉。 | 实际打开的宽度 + 发现并修掉的问题。 |
| 12 | 数字用图表 | 表示多少的数字，是不是都画成了图？ | 逐处找页面里表示多少的数字（数量、次数、金额、时长、百分比、用量）：每一个都按 `INFO_SUMMARY_HTML_RULES.md` 的 `数字用图表` 画成了图（柱状图、折线图、进度条、点状图、数字卡片），没有只写在句子里，也没有用表格代替图；结论句里引用的数字也在图上；图上有数值和单位；只有日期、编号、ID 留在文字里。页面里没有表示多少的数字时 ⚪N/A。 | 找到的每处数字 + 各用了什么图。 |

### 信息汇总 Review Report Shape

和 `AGENTS.md` 的 `Answer Review` 一样：检查全部照做，回答里只写结果，有问题才展开。

| 情况 | 回答里怎么写 |
|---|---|
| 全部 ✅ / ⚪N/A | 只写一行：`✅ N/12 通过，M 项 N/A`；有适用的 Conditional checks 时补 `；条件检查 a/b 通过`。 |
| 有 ❌ 或 🟡 | 先写一行 `⚠️ N/12 通过，M 项 N/A，K 项要注意：`，再用三列表（检查、状态、证据）只列 ❌ / 🟡 的那几项（包括 Conditional checks），按检查顺序，每行一句真实证据。❌ 按 Fix loop 先改好；只有改不了的（例如要等 Human 决定）才留在表里，并写进 `➡️ 只有 Human 能做的事`。 |
| 本轮因 review 修过东西 | 在那一行后面补一句修了什么（包括为了去重、去冲突改的其他汇总）。 |
| 本轮没有新建或更新信息汇总 | 整个 section 只写 `➖ N/A`。 |

## Conditional Requirements

### Conditional Review Map

| 条件 | 必须 Review |
|---|---|
| 从旧的 Markdown 汇总迁移，或合并多个汇总 | 迁移不丢内容。 |
| 把旧版式的汇总换成新版式 | 改版不丢内容。 |
| 页面给团队看 | 团队语言。 |
| 项目 `PROJECT_LOCAL_OVERRIDES.md` 改了位置或样式 | 项目规则优先。 |

### Conditional Review Checks

| 条件 / 检查项 | 一句话说白了 | 怎么判断 | Evidence |
|---|---|---|---|
| 迁移不丢内容 | 旧文件里有用的内容都搬过来了吗？ | 旧文件的每一块在新汇总里都有对应位置，确认后才删旧文件。 | 旧块 → 新块的对照。 |
| 改版不丢内容 | 换版式时有没有漏东西？ | 旧页面的每一块、图里的每个组件和关系、Q&A 每一条，在新页面里都有对应位置。 | 旧块 → 新块的对照。 |
| 团队语言 | 团队看的页面是不是 English？ | 标题、表格、图里的字都是 English。 | 页面文字。 |
| 项目规则优先 | 有项目规则时按项目规则做了吗？ | 位置、文件名、样式按 `PROJECT_LOCAL_OVERRIDES.md`。 | 对应的 override 那一条。 |
