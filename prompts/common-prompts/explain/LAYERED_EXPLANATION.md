# 一层一层讲解问题

来源：v-project `prompts/common-prompts/explain/2026-10-22-layered-explanation-prompt.md`（2026-10-22，从 AZZU-3296 测试 2 的讲解方式整理）；2026-10-24 升为 Common 共享规则；2026-11-02 并进 `说白了核心是这几件事`，改用卡片显示。

## 什么时候用

- **平时**：`## 🧭 说白了核心是这几件事` 本来就按层写：后一件要先懂前一件就编号成层，互不依赖就不编号（规则在 `AGENTS.md` 的 `核心几件事 = 图里没有的东西，一层一层讲`）。
- **加深**：Human 说看不懂、搞不清楚、很懵，或明确要求讲解 / 讲详细 / 一层一层讲时，按本文件把这些层讲得更深；可以超过 3 层。
- **说不出哪里不懂**：Human 只说看不懂、说不出卡在哪时，AI 先列 3 个最可能卡住的点（每个一行，加粗重点词）让 Human 选；Human 选了哪个，只讲那一个。
- **默认不加深**：其他情况保持 AGENTS 的默认短回答，不主动展开。
- **记进看不懂记录**：Human 说看不懂，或指出回答哪里难读（例如 English 用多了、漏了重点、图看不懂）时，AI 在当前 repo 的看不懂记录 `info-summary/YYYY-MM-DD-看不懂记录-信息汇总-Summary.html` 里加一条 👎（Human 说好的回答记 👍，见 `AGENTS.md` 的 `好例子`）：时间线加一个点（日期、👍 / 👎、哪个 section / 东西、为什么、处理了吗），主图里对应 section 的数字加一；页面不存在就从信息汇总模板建，并在总索引加一行。只往后加，不删旧记录；后来哪个 PR 修好了这一条，就在那个点的详情里写上 PR 号，状态块只留还没处理的。Human 不用做任何事。为什么：攒几条同类的再改规则，改的方向就有 evidence；不是每次看不懂都马上加一条新规则（2026-11-13 Human 定）。读不到项目的网页 Chat 不记。

## 怎么拆

- 先想清楚 Human 真正卡在哪里、想知道什么，再决定怎么拆；拆法按具体问题来定，目标是最容易看懂。
- 每一层只讲一个概念，后一层建立在前一层上，从 Human 已经懂的地方讲到不懂的地方。
- 常见拆法（只是例子，不是固定步骤）：目标 → 机制 → 难点 → 方案对比 → 细节和边界 → 证据；用不上的层就不要。

## 格式

- **Markdown（一直要写）**：按 `AGENTS.md` 的 `Markdown 问答表`，用两列表 `问题 | 一句话说白了`，每层一行，问题写“第 N 层：<这一层回答什么>”，答案在冒号后用 `<br>` 换行；需要更多内容时，表格下面可以加小表或文字进度条。
- **卡片（Human 要求卡片、而且能显示时另外加）**：用 `prompts/common-prompts/templates/ANSWER_CARD_TEMPLATE.html` 的分层样式：每层一张白卡，左边标“第 N 层”（第 0 层起），标题写这一层回答什么，下面 1～3 句，需要时加一个小图（从 `HTML_PAGE_RULES.md` 的 `常用图形` 里选）或小表。
- **不用树状文字**：不用 text 代码块画树（├── └──），它会把字变小、没法加粗，看不出重点。
- **第 0 层**：通常用一两句话说清楚“我们到底想要什么”。
- **写具体**：资源名、订阅名等写具体名字，不模糊；标明哪些是实测、哪些是推断；emoji 只用来标状态（✅ ❌ ⚠️）。

## 语言

- 中文大白话，像跟同事口头讲；技术术语保留英文。
- 不堆背景，不重复，每层 1～3 句。

## 结尾

- **总结**：一句话总结放在 `## 🎯 一句话说白了结论` 里（有卡片时也放在卡片顶部）。
- **不请 Human 讲回来**：结尾不请 Human 讲回来，也不在 `## ➡️ 只有 Human 能做的事` 里加这类问题。Human 自己用自己的话讲回来时，按 `AGENTS.md` 的 `三轮弄懂一个问题` 回：✅ 哪部分对 + 🔧 最多 2 处必须改的，然后结束。
